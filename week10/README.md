# Practical Design Patterns Lab

Java SE 8+, только стандартная библиотека. Maven, Gradle и внешние зависимости не нужны.

## Запуск в VS Code

Откройте эту папку через File → Open Folder. Если установлен Extension Pack for Java,
выберите Task 1–5 в Run and Debug (F5) либо нажмите Run над нужным main.
Без расширений выполните во встроенном PowerShell:

```powershell
./run.ps1          # все пять демонстраций
./run.ps1 3        # отдельная задача
./run.ps1 test     # компиляция и проверки поведения
```

Нужен JDK с поддержкой `javac --release 8` (JDK 9+). Полученные классы совместимы с Java 8.

## Архитектура

| Пакет | Паттерны | Назначение |
| --- | --- | --- |
| task1 | Strategy + Decorator | JSON/CSV и композиция экспортёров |
| task2 | Adapter + Proxy | Разбор старого feed и TTL-кэш |
| task3 | Bridge + Strategy | Email/SMS независимо от типа уведомления и политики |
| task4 | Adapter + Decorator | GBP → USD, упаковка, доставка, пошлина |
| task5 | Bridge + Proxy | Видео/аудио, S3/NFS и проверка роли |

Каждый публичный тип находится в отдельном файле. Пять TaskNRunner перенесены из
PDF без изменения тела. `test/LabTests.java` проверяет вычисления и взаимодействия
паттернов без JUnit. `verification.txt` содержит результаты фактического запуска.

## Неоднозначности исходного задания

При расхождениях текста, skeleton и ожидаемого вывода сохранены API и поведение
immutable Runner и skeleton. Это позволяет запускать предоставленные проверки.

- Task 1: `Base64(HeaderFooter(file))` сначала кодирует исходные данные, затем
  внутренний HeaderFooter добавляет открытые метаданные. Образец в PDF показывает
  противоположный порядок и неверное количество байтов. Реализация считает реальные
  UTF-8 байты. Чтобы кодировать и метаданные, поменяйте порядок обёрток в отдельном клиенте.
- Base64 — кодирование, а не шифрование. Название Base64EncryptDecorator сохранено
  для совместимости. Строка SHA-256 OK — учебный маркер из skeleton, хэш не вычисляется.
- Task 2: возраст кэша зависит от времени выполнения; значение 2 ms не фиксируется.
  TTL отсчитывается после получения ответа монотонными часами; регистр тикера
  нормализуется. Кэш цены ограничивает повторные upstream-вызовы; отдельный лимит
  запросов и кэш статуса в skeleton не заданы. getStatus делегируется напрямую.
- Task 3: сохранены processAlert, тексты каналов и сообщений из skeleton.
- Task 4: сохранён convert из skeleton; результат округляется после пошлины,
  итог предоставленного примера — $157.33.
- Task 5: разрешены ADMIN, MEMBER и ENGINEER (в PDF используются оба названия
  обычной роли). Неизвестная, пустая и null-роль блокируются, как GUEST.
  Сессия неизменяема. Настоящие токены и проверка их подлинности в PDF не определены.
- Все внешние операции симулируются: экспорт не пишет файл, SMS/email не отправляются,
  S3/NFS не подключаются.
